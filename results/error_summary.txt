================================================================================
CRITICAL — DATA CORRUPTION
================================================================================

1. EMBEDDED HEADER ROWS IN PiF RAW CSVs
   Four PiF raw files contain a stray header row inserted mid-data, concatenating
   two runs with different schemas:
   - qwen/harmbench/results.csv:    embedded header at row 107 (schema A→B switch)
   - qwen/strongreject/results.csv:  embedded header at row 10
   - llama/harmbench/results.csv:    embedded header at row 244 (same schema both sides)
   - falcon/harmbench/results.csv:   embedded header at row 279 (same schema both sides)
   Impact: naive readers using the first header row will misalign columns for
   rows after the embedded header. Row counts are inflated by 1 per embedded row.
   qwen/harmbench is worst: column names change mid-file
     (target→victim, jailbreak_prompt→pif_prompt, target_response→victim_output,
      asr_gpt→judge_gpt).

2. COLUMN SCHEMA INCONSISTENCY ACROSS PiF RAW FILES
   Two schemas coexist:
   Schema A: prompt_idx, dataset, target, original_prompt, templated_prompt,
             jailbreak_prompt, target_response, attack_success_internal,
             asr_gpt, total_query, pif_time_s, total_time_s
   Schema B: prompt_idx, dataset, victim, original_prompt, templated_prompt,
             pif_prompt, victim_output, attack_success_internal, judge_gpt,
             total_query, pif_time_s, total_time_s
   qwen/harmbench uses schema A as the top-level header (switches to B at row 107).
   All other files use schema B. PIF_JUDGED standardized on schema B.

3. FIGURE 2 HARDCODED MDG MISMATCHES COMPUTED ASRs
   plots/fig-2-exposure_metrics.py has hardcoded MEE/MDG that don't match judged CSVs:
   Model       Computed MEE  Fig-2 MEE  Computed MDG  Fig-2 MDG  MDG diff
   Qwen2.5         71.5        71.0        59.9         53.9      +6.0 !!!
   Llama-3.1       71.1        70.5        57.9         47.4     +10.5 !!!
   Falcon          24.8        24.8        24.8         24.6      +0.2
   DiffuCoder      31.5        31.5        30.6         31.4      -0.8
   Dream           13.9        13.9        13.9         13.9       0.0
   LLaDA           77.6        77.0        70.0         69.2      +0.8
   MEE values are close (≤0.6pp, likely rounding). MDG for Qwen and Llama differ
   by 6.0 and 10.5 percentage points — figure likely generated from earlier results
   or a different ASR computation method.


================================================================================
SIGNIFICANT — SCHEMA / NAMING INCONSISTENCY
================================================================================

4. ArrAttack LLaDA RAW MISSING 2 COLUMNS
   All ArrAttack raw files have 18 columns (global_idx, dataset, dataset_idx,
   prompt_idx, ...). LLaDA has only 16 — missing global_idx and dataset_idx.
   Column order also differs (LLaDA starts: prompt_idx, dataset, original_prompt).
   Scripts reading by positional index or expecting global_idx will break on LLaDA.

5. DATASET NAME CASING INCONSISTENCY
   - ArrAttack LLaDA: capitalized dataset names (HarmBench, JailbreakBench,
     MaliciousInstruct, StrongReject) vs lowercase in all other models.
   - PiF strongreject: llama uses "strong_reject" (underscore) as directory name,
     all others use "strongreject" (no underscore). File content is identical.

6. BOM IN SOME PIF_JUDGED HEADERS
   3 of 6 PIF_JUDGED files have a UTF-8 BOM (\ufeff) prefix on the first column
   name ("\ufeffprompt_idx"): qwen, llama, diffucoder. The other 3 (falcon, llada,
   dream) do NOT have a BOM. pandas.read_csv column lookups will fail on the
   BOM-affected files unless encoding='utf-8-sig' is used.

7. MISSING UNIFIED JUDGE SCRIPT
   scripts/evaluation/judge.py contains KeywordJudge and LLMJudge classes, but
   neither produces the columns found in the judged CSVs (asr_success, llm_judge,
   gpt_fuzz, prompt_type, is_too_general_prompt, manual_review_note, etc.).
   The actual unified judge that produced *_Judged/ files is NOT in the repo.
   judge.py appears to be an unused placeholder.
   Additionally, judge.py has a hardcoded path: sys.path.append('/scratch/si2356/
   projects/dlm-jailbreak-transfer') — another user's HPC scratch path.

8. ArrAttack JUDGED COLUMN MISALIGNMENT WITH NON-CSV PARSERS
   When parsed with awk -F',' (positional), the asr_success column (field 10)
   contains garbage from final_response bleeding through (commas inside quoted
   fields). Proper CSV parsing (csv module / pandas) is correct: 22 columns,
   clean True/False. Any analysis script not using a CSV-aware parser will fail.

9. ArrAttack MODEL DIRECTORY NAMING
   Qwen2.5 stored under "Qwen2.5" (capitalized) while judged file is
   arrattack_01_qwen2_5_judged.csv. Other models use lowercase directories.


================================================================================
MODEL BEHAVIOR ISSUES (documented findings, not data bugs)
================================================================================

10. FALCON CoT LEAKAGE
    Falcon-H1R responses across all three attacks begin with
    "assistant\n<think>\nThe user is asking..." — internal reasoning/CoT leaks
    into output before the actual (often refusing) response. The literal text
    is "<think>" (not an emoji).
    Impact: PiF internal judge counts these as successes (long text, no early
    refusal keyword). Unified judge correctly rejects them (judge_reason =
    "answer_opens_with_refusal"). Any keyword-based judge will also be confused.
    Scale: 835/913 PiF prompts for Falcon have raw=True→judged=False.

11. MetaCipher INTERNAL JUDGE MASSIVE FALSE POSITIVES (Dream, DiffuCoder)
    Raw "success" vs unified judge "asr_success" disagreement:
    Model       Agree  Raw=True→Judged=False  Raw=False→Judged=True
    Qwen         671          217                    25
    Falcon       821           92                     0
    Llama        672          105                   136
    LLaDA        569          270                    74
    Dream        251          662 (!)                0
    DiffuCoder   267          644 (!)                2
    Dream and DiffuCoder internal judges mark 663/650 as success, but unified
    judge reclassifies 662/644 as failures (mostly too_general / wrong_decryption).
    Confirms README: "MetaCipher×DiffuCoder successes are overwhelmingly scaffold
    artifacts." Extends to Dream.

12. ArrAttack ORIGINAL JUDGE (GPTFuzz) RETURNS 0% FOR FALCON
