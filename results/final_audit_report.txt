--- 1. PIF llada/llama CROSS-LABELED results (NEW, most serious) ---
  The `victim` column disagrees with the file/directory it lives under
  for the PIF jailbreakbench subset (both models) and llama's
  malicious_instruct. A reader trusting the file NAME to mean "this
  model's results" will assign these 300 rows to the wrong model.

  Judged files (victim col not constant within file):
  * pif/PIF_JUDGED/llada_pif_final_judged.csv
      100/913 rows have victim='llama' (all jailbreakbench).
  * pif/PIF_JUDGED/llama_pif_final_judged.csv
      200/913 rows have victim='llada' (jailbreakbench 100,
      malicious_instruct 100).

  Raw files (file location vs victim col mismatch):
  * pif/llada/jailbreakbench/results.csv  -> victim=['llama'] for all 100
      (llama's jailbreakbench data sits in the llada dir)
  * pif/llama/jailbreakbench/results.csv  -> victim=['llada'] for all 100
      (llada's jailbreakbench data sits in the llama dir)
  * pif/llama/malicious_instruct/results.csv -> victim=['llada'] for all 100
      (llama dir holds llada-labeled MI)
  Consistent (for contrast): pif/llada/malicious_instruct/results.csv
      victim=['llada'] (correct).

  Cross-check (not a copy artifact):
  * llada and llama judged files share 913/913 (dataset,prompt_idx) keys
    but have identical response text for only 2 of them, and 0 identical
    on jailbreakbench -> the two models' jailbreakbench (and llama MI)
    outputs are genuinely SWAPPED between the result sets, not merely
    relabeled copies.
  * ASR of the mislabeled subsets (llm_judge): llada-file's 100
    llama-labeled rows -> 8 True / 92 False; llama-file's 200 llada-
    labeled rows -> 9 True / 191 False.

  Impact: per-model PIF ASR for jailbreakbench (llada and llama) and for
  llama/MI is computed from the wrong model's responses unless the reader
  keys on the `victim` column instead of the file name. Recommended
  before publication: regenerate or re-verify the llada/llama
  jailbreakbench and llama/MI runs.
