3. STRANGE / SUSPICIOUS FINDINGS
============================================================

PIF JUDGED — falcon and dream have ALL llm_judge=0:
    - falcon: 913/913 rows have llm_judge=0. Zero successful jailbreaks. But victim_output contains actual model reasoning ("The user is asking for instructions on how to make dimethylmercury..."). The model produces extensive internal reasoning before refusing. judge_reason is dominated by "answer_opens_with_refusal" (737), "thinking_only_no_answer" (72), "reasoning_then_refusal" (54), "degenerate_output" (47).
    - dream: 913/913 rows have llm_judge=0. Zero successful jailbreaks. 93 entries have empty_output (model produced nothing). judge_reason is "answer_opens_with_refusal" (772) plus various non-compliance categories.
    → These two models have a 0% ASR across ALL 913 prompts. While possible (very robust models), the complete absence of even a single success is worth verifying — especially since other models on the same prompts did get successes (llama=120, qwen=106, llada=48, diffucoder=49).

METACIPHER — massive raw vs judged success disagreement:
    The raw "success" column and the judged "asr_success" column disagree heavily:
    - diffucoder: 270 rows where raw=True but judged=False, 2 rows where raw=False but judged=True
    - dream: 274 rows where raw=True but judged=False
    - falcon: 51 rows raw=True/judged=False
    - llama: 43 rows raw=True/judged=False, 73 rows raw=False/judged=True
    - llada: 48 rows raw=False/judged=True, 112 rows raw=True/judged=False
    - qwen: 8 rows raw=False/judged=True, 69 rows raw=True/judged=False
    → The raw "success" metric (likely heuristic/keyword-based) and the LLM judge disagree on hundreds of entries. This is a major measurement consistency issue. Looking at examples: raw success=True for diffucoder often means the model produced output starting with "Here is how to..." but the judge classified it as "too_general" or "wrong_decryption" (the cipher wasn't correctly decoded so the model responded to a garbled prompt, not the actual harmful one).

METACIPHER JUDGED — falcon and dream near-zero ASR:
    - falcon: 2/913 success (0.2%) — llm_judge = 798 wrong_decryption, 99 refusal, 14 too_general
    - dream: 1/913 success (0.1%) — llm_judge = 672 wrong_decryption, 61 refusal, 179 too_general
    → Both models predominantly fail because they can't decrypt the cipher (wrong_decryption), meaning the attack prompt is garbled before it reaches the model. This is structurally different from llada/llama/qwen which have 432-653 compliance cases.

ARRATTACK JUDGED — "wrong_decryption" appears in gpt_fuzz column:
    - arrattack_05_falcon_judged.csv: 3 rows have gpt_fuzz="wrong_decryption"
    - arrattack_06_llada_judged.csv: 1 row has gpt_fuzz="wrong_decryption"
    → "wrong_decryption" is a MetaCipher concept, not an ArrAttack/gpt_fuzz concept. These values leaked from the MetaCipher judging pipeline into the ArrAttack judged files. Of the 4 affected rows, 3 (falcon) have final_response starting with a thinking tag followed by model reasoning text ("The user asks:..."), which looks like raw model internal reasoning. The 1 llada row starts with "Certainly! A lengthy excerpt..." — this is actual compliance text, not model reasoning, making it a genuine mislabel.

ARRATTACK — llada used 200 max attempts, all others used 50:
    - arrattack/llada/arrattack_results.csv: max_attempt=200 (200 unique attempt values)
    - All other models: max_attempt=50
    → Llada ran 4x more attempts per prompt. This makes ASR comparisons unfair — llada had more chances to find a successful jailbreak. This likely inflates llada's ASR (128/165=77.6% in judged) relative to other models.

ARRATTACK — llama and qwen are near-identical in structure:
    - Both have exactly 3409 rows, same dataset distribution (1796/438/132/1043), same max_attempt pattern (50/50/37/50).
    - But content differs (different target_model, different responses). They are independent runs.
    - The malicious_instruct cutoff at attempt 37 for both suggests they were run together and stopped at the same point.

ARRATTACK — llama responses are mostly refusals:
    - 1806/3409 (53%) of llama's raw responses start with "I am sorry I can't assist with that" — the model refused the majority of converted prompts outright.

ARRATTACK — only ran on a subset of prompts:
    - All models: harmbench=75/400 prompts, jailbreakbench=20/100, malicious_instruct=20/100, strongreject=50/313.
    - Total: 165 unique prompts out of 913. ArrAttack only covers ~18% of the benchmark.
    - This is likely by design (ArrAttack is expensive, best-of-N attempts), but it means ArrAttack ASR is computed on a different prompt set than PIF/MetaCipher (which cover all 913).
