PURPOSE AND REVISION STANDARD

This plan addresses every weakness (W1-W12), every requested change (RC1-RC20) and the broader-impact concerns in the R4 mock review. The goal is a manuscript whose claims, protocols, statistics, artifacts and ethics statements are internally consistent and reproducible from a row-level ledger. No editorial outcome can be guaranteed. The review lists RC1-RC10 as critical to an acceptance recommendation; those are the submission blockers (priority P0). Every other item either strengthens the paper (P1) or is optional (P2); an item that is not done must appear as an explicit limitation, with no unsupported claim left in the paper.

The plan is ordered by dependency. Phase 1 uses only data already on disk and should be finished first. Its results determine how much regeneration Phase 2 actually needs, and several P0 items can be closed in Phase 1 without new GPU time.


WHAT CHANGED FROM v1

- Reorganized into dependency-ordered phases. Audits of existing data come first and set the scope of any regeneration.
- Realigned priorities with the review. v1 marked the full-pool ArrAttack rerun, whole-matrix decoding standardization and source-paper reproduction as critical. The review lists these as strengthening items (RC13, RC14, RC16), and doing all of them would amount to rerunning the main matrix. v2 closes the underlying critical concerns with cheaper P0 steps: a paired comparison on the 165 common prompts, an LLaDA-only schedule lock, a seed and greedy sensitivity sample, and a PiF similarity audit. The large reruns remain as P1.
- Added three Phase 0 decisions that v1 left implicit: the primary common judge and rubric (D3), the attempt and adaptivity protocol (D4), and a frozen statistical analysis plan (D7).
- Corrected the status of the LLaDA bracket discrepancy. It is a same-response re-judgment of 50 stored rows, not a regenerated estimate.
- Added a 2x2 decomposition (stored versus regenerated responses, crossed with judge) to find the root cause of the Llama 71.1% versus 11.4% gap. v1 only relabeled the gap.
- Replaced the blanket single-attempt rule with an explicit, equal attempt budget: ASR@1 primary, ASR@k secondary. Also added a frozen-policy option that would turn MetaCipher into a genuine transfer setting.
- Gave the human calibration a concrete annotator protocol with welfare safeguards, and stated the consequence if it is not approved.
- Added a compute approval gate, output conventions, an anonymity scrub, a highlighted-changes PDF, a response letter, a risk register with pre-committed claim updates, and a complete RC1-RC20 map.
- Merged duplicated items (v1 T10/T19/T22, T1/T24, T20/T26, T21/T27) and removed hard line wraps.

GLOBAL GUARDRAILS

1. Row identity. Create one canonical, immutable row key from benchmark identity and original prompt identity. Never join or deduplicate rows by normalized prompt text alone. Keep every missing, malformed, empty, failed or excluded row, with an explicit status and reason.
2. One response per prompt. Each reported run has one final attacked prompt, one final victim response and one verdict per original prompt under the attempt protocol frozen in D4. Never concatenate attempts, never select best-of-N, and never silently discard failed rows.
3. Freeze before outcomes. Freeze attack, victim, decoding and judge configurations before inspecting new outcome labels. Preserve the existing run as an as-run reference. Never tune a configuration to raise or lower ASR.
4. Reporting. Every reported proportion includes numerator, denominator and an interval. Use paired tests for paired prompt comparisons, and prompt-clustered or duplicate-cluster-aware uncertainty for pooled analyses. Reweight stratified samples before making marginal claims.
5. Judge versus generation. A judge comparison is valid only when all judges score the exact same stored response. Analyses on regenerated responses measure generation variability, not judge disagreement.
6. No ground truth. Never call GPT-5.6-sol, any other LLM judge or a judge majority ground truth. Absolute harmful-compliance rates remain uncalibrated unless an approved human reference set is actually collected and reported.
7. Harmful text. Harmful response text stays access-controlled. Reviewer-facing material contains row IDs, metadata, verdicts, status fields, response hashes, scripts and sanitized examples, never unrestricted operational completions.
8. Compute approval gate. No HPC job submission and no large API batch without Boyuan's explicit approval. Each request states the task ID, purpose, frozen configuration hash, row count, estimated GPU-hours or API calls and cost, and output location. Do not launch until approval is given.
9. Output conventions. All artifacts go under revision_experiments/r4/, one subfolder per task ID. All JSON is written with indent=4. Every table and figure input is built by a script from the row ledger, never by hand.
10. Anonymity. Nothing in the manuscript, package or reviewer-facing logs may contain author names, usernames, home-directory paths, cluster or institution names, job IDs, account identifiers or git author metadata.
11. Completion rule. An item is complete only when its data artifact, analysis script, manuscript change and verification note all exist. Record every decision, with date and rationale, in a decision log (JSON, indent=4).
