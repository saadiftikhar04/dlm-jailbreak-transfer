# A2 attempt/adaptivity audit, C0 complete with recovery limits

Scope: existing files only. No model inference, API calls, or generation was run. The reproducible count/hash checks are in `a2_attempt_audit.py`; the machine-readable, response-text-free output is `a2_attempt_audit.json`.

## PiF attempt control relevant to D4

The PIF runner queries the victim inside up to 50 prompt-optimization iterations and stops when its rejection-prefix heuristic accepts a response. The judged CSV stores only the returned final `victim_output` plus `total_query`; the step log stores prompt rewrites, not intermediate victim responses. For causal victims, the first response is present only when `total_query=1`; missing first responses are Qwen 664, Llama 761, and Falcon 194. For diffusion victims, `run_pif.py` overwrites the optimizer's response with an additional `target_generate` call on the chosen final prompt, so the first optimizer response is absent from the row artifact for all 913 rows per victim, 2,739 rows total. Overall, 4,358 PiF first-query responses are not present in the row ledger. This was not explicit in the R4 A2 bullets, but it is required by D4's global attempt/provenance guardrail.

## MetaCipher

- Each of the six judged cells has 913 rows, and every saved judged response exactly matches the corresponding `target_response` in the raw per-victim result file under the composite `(dataset, prompt_idx, original_prompt)` key. This is one selected response per prompt, not evidence that multiple responses were concatenated into one cell.
- The stored `attempts` value ranges from 1 to 5 and every judged response matches the one raw `target_response` saved for its row. The judged CSV copies this value into both `final_attempt` and `total_attempts`; those equal columns do not prove the number of chronological victim queries. The checked local implementation reuses a framework and Q-table across prompts, returns on its categorical success condition, and otherwise retains the highest-reward failure, but the exact source revision that produced each historical cell is not preserved. We therefore record adaptive behavior as the checked-code design and leave the executed attempt-selection rule unknown where logs do not establish it.
- The row ledger's stored selection index is greater than 1 on 3,464 rows total (per-victim counts in `a2_attempt_audit.json`); 2,752 of those are attack-specific failures and 712 are successes reached after multiple attempts. These selected-response rows are not ASR@1 evidence. Exact first-response recovery from historical logs is not yet established, so do not relabel them as ASR@1.

## ArrAttack

- Within ArrAttack's held-out artifact, `(dataset, prompt_idx, original_prompt)` identifies each saved row, but its `prompt_idx` is local to the selected tail for that benchmark, not the 913-pool index. For cross-attack comparisons, map the stored original text and its verified selected-tail order back to the immutable `(dataset, prompt_idx)` key in `pool_913.csv`; do not directly join ArrAttack's local index to the PiF/MetaCipher pool index. A5 verifies this mapping for all four tails and all six victims.
- For all six victims, each of the 165 judged responses matches a raw per-attempt response at the attempt identified by `best_attempt`; each also matches the maximum numeric attempt in its correctly keyed candidate group. `total_attempts` matches the raw candidate-row count for all 165 prompts per victim. The stored held-out output is therefore the last saved numeric attempt, not a demonstrated maximum-score selection. The earliest victim-query response is recoverable from the raw attempts for all 990 held-out rows; one DiffuCoder prompt has three duplicate attempt-1 records, but their response hashes are identical.
- There is one repeated intermediate attempt index in the DiffuCoder raw group; its selected maximum attempt is unique. No held-out raw group exceeds 50 attempt rows after applying the canonical key. The earlier apparent cross-cell duplicates and selection discrepancies came from grouping on prompt text without the dataset/index key and are invalid.
- `dual_judge.py` contains a separate best-of-N selection routine, but the row-level match above does not show that routine produced the current 165-prompt files. The current held-out records instead map to their maximum-numbered saved attempt. Keep the withdrawn full-pool max-score re-judge separate from this held-out result.
- The 300-prompt-per-seed ArrAttack cells in the multiseed table have a distinct, now-verified provenance: `sample_multiseed_r2.py` samples stratified prompts from the 913-prompt full-pool ArrAttack artifacts, and `gen_multiseed_r2.py` regenerates victim responses for three seeds. The 2,700 ArrAttack rows in `multiseed_judged.jsonl` are a common-judge seed-sensitivity analysis, not the 165-prompt held-out estimate and not extra observations to pool into its denominator.
